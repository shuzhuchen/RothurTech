## jdbc vs hibernate
JDBC is a Java API used to communicate with databases. With JDBC, we need to write SQL manually and use RowMapper to map database records into Java objects.

The advantage is that we have full control over the SQL. The disadvantage is that there is a lot of boilerplate code, and if the database schema changes, we may need to update the SQL and RowMapper manually.

Hibernate is an ORM framework. Instead of writing SQL and RowMapper ourselves, we define mappings using annotations such as @Entity and @Column, and Hibernate automatically generates SQL and maps database records to Java objects.

Hibernate improves development efficiency, but for very complex queries, we can still write custom SQL or JPQL when needed.

## Statement vs PreparedStatement vs CallableStatement
Statement builds SQL using string concatenation.

For example:

```
String sql = "select * from user where password = '" + userInput + "'";
```

This is dangerous because it can lead to SQL injection.

PreparedStatement uses placeholders represented by question marks.

It separates SQL logic from user input and automatically handles parameter binding, which helps prevent SQL injection. This is the most commonly used approach.

CallableStatement is used to execute stored procedures that are already defined in the database.

## how to prevent sql injection
SQL injection happens when users enter SQL logic instead of normal input.

For example: ' OR 1=1

This may change the intended SQL behavior and bypass authentication.

The most common way to prevent SQL injection is to use PreparedStatement instead of Statement.

PreparedStatement uses placeholders and parameter binding, so user input is treated as data rather than executable SQL.

We should also validate user input and avoid building SQL using string concatenation.

## JPA vs Hibernate
JPA stands for Java Persistence API. JPA is a specification, which means it defines a set of rules and interfaces for ORM.

Hibernate is one implementation of JPA. In Spring Boot, we usually use Spring Data JPA, which sits on top of Hibernate and provides convenient methods such as save(), findById(), and delete(). So JPA is the standard, and Hibernate is the implementation.

## what are the Persistent State in Entity LifeCycle
In Hibernate, an entity usually goes through four states: Transient, Persistent, Detached, Removed.

Transient means the object is created using new, but it is not managed by Hibernate yet.

Persistent or Managed means the entity is attached to the current Hibernate session. Any changes made to it will automatically be synchronized to the database when the transaction commits.

Detached means the entity was previously managed, but the session has been closed. Changes are no longer tracked.

Removed means the entity has been marked for deletion and will be removed from the database when the transaction commits.

## Mapping relationship
To map a Java class to a database table, we use annotations such as @Entity, @Id, and @Column.

For relationships between tables, Hibernate provides four main mapping annotations.

@OneToOne represents a one-to-one relationship.

@OneToMany represents one parent with multiple children.

@ManyToOne represents many records pointing to one parent.

@ManyToMany represents many records on both sides.

We often use @JoinColumn to specify the foreign key column.

## what is the cascade type
Cascade type controls whether operations on a parent entity should automatically apply to child entities. For example, CascadeType.PERSIST means when we save the parent, Hibernate also saves the child entities.

CascadeType.REMOVE means deleting the parent will also delete the children.

CascadeType.ALL includes all cascade operations. It helps me manage related entities without writing extra code.

## what is the fetch type
Fetch type controls when related entities are loaded from the database.

FetchType.LAZY means child entities are loaded only when we access them. This improves performance because unnecessary data is not loaded.

FetchType.EAGER means child entities are loaded immediately together with the parent entity.

In most cases, LAZY loading is preferred because it reduces memory usage and improves query performance.

## what is the first/second level cache
The first-level cache is enabled by default in Hibernate. It exists inside a Hibernate session. If the same entity is queried multiple times within the same session, Hibernate returns it from the cache instead of querying the database again.

The second-level cache is shared across multiple sessions. It is typically used for frequently accessed data, such as product categories or top-selling products, so different users can reuse the same cached data without repeatedly hitting the database.

## left join vs right join vs inner join vs outer join vs cross join
Inner Join returns only records that exist in both tables.

Left Join returns all records from the left table. If there is no match in the right table, the right-side columns are returned as NULL.

Right Join is the opposite and returns all records from the right table.

Full Outer Join returns all records from both tables, regardless of whether a match exists.

Cross Join creates a Cartesian product. Every row in the first table is combined with every row in the second table.

## union vs union all 
Both Union and Union All combine the results of multiple queries.

The difference is that Union automatically removes duplicate records, while Union All keeps all records including duplicates.

Because Union needs to perform duplicate checking, it is usually slower.

Union All is generally faster and should be used when we know duplicates are not a concern.
