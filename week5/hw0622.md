# Spring Cloud Eureka

## what is and why we use Eureka

Eureka is a service registry originally provided by Netflix and well integrated with Spring Cloud. Its main role is to let microservices register themselves at runtime and allow other services to discover them by service name, avoiding hardcoded host and port values in code or configuration.

In a microservice environment, relying on fixed host and port addresses causes tight coupling and makes scaling and maintenance harder. Eureka addresses these issues.

## Core Idea

- Services register themselves with the Eureka Server when they start.
- Callers use the service name; Eureka maps the service name to real instance addresses.
- When services move, scale, or change ports, only the registry needs updating — callers remain unchanged.

Example:

Direct call (fragile):
```java
http://localhost:8848/payment-provider/payNow/4000
```

Via Eureka (flexible):
```java
http://PAYMENT-SERVICE/payment-provider/payNow/4000
```

## Demo

This tutorial uses three Spring Boot applications:

- Eureka Server (registry, default port 8761)
- Payment Service (provides payment API, service name `PAYMENT-SERVICE`)
- Shopping Service (client, calls Payment via Eureka)

Request flow: User -> Shopping -> Eureka -> Payment -> Shopping -> User

## Quick Start Highlights

1) Eureka Server

- Dependencies: Spring Web, Eureka Server, DevTools
- Main class annotated with `@EnableEurekaServer`
- Example `application.yml`:
```yaml
server:
  port: 8761

spring:
  application:
    name: amazon-server

eureka:
  client:
    register-with-eureka: false
    fetch-registry: false
```

2) Payment Service

- Dependencies: Spring Web, Eureka Discovery Client, DevTools
- Main class annotated with `@EnableEurekaClient`
- Controller example:
```java
@RestController
@RequestMapping("/payment-provider")
public class PaymentController {
    @GetMapping("/payNow/{price}")
    public String payNow(@PathVariable int price) {
        return "Payment with " + price + " is successful";
    }
}
```
- Example `application.yml`:
```yaml
server:
  port: 8848

spring:
  application:
    name: PAYMENT-SERVICE

eureka:
  client:
    register-with-eureka: true
    fetch-registry: true
    service-url:
      defaultZone: http://localhost:8761/eureka/
```

3) Shopping Service

- Also annotated with `@EnableEurekaClient`, example port 9999 and service name `SHOPPING-SERVICE`.
- Register a `RestTemplate` bean with `@LoadBalanced`:
```java
@Bean
@LoadBalanced
public RestTemplate restTemplate() {
    return new RestTemplate();
}
```

Call example (ShoppingController):
```java
@Autowired
private RestTemplate restTemplate;

@GetMapping("/amazon-payment/{price}")
public String invokePaymentService(@PathVariable int price) {
    String url = "http://PAYMENT-SERVICE/payment-provider/payNow/" + price;
    return restTemplate.getForObject(url, String.class);
}
```

## Common Annotations and Config Tips

- `@EnableEurekaServer`: declares the app as a Eureka Server.
- `@EnableEurekaClient`: registers the app as a Eureka client.
- `@LoadBalanced`: enables service-name-based calls and simple load-balancing for `RestTemplate`.

- Clients must set `spring.application.name` and `eureka.client.service-url.defaultZone` in `application.yml`.
- Eureka Server should set `register-with-eureka: false` and `fetch-registry: false` to avoid self-registration or pulling registry data.

## Key Points

- Eureka provides service registration and discovery, removing reliance on fixed host/port addresses.
- Calling by service name improves flexibility for scaling and migration.
- Practical advice: set clear `spring.application.name` for each service and ensure clients can reach the Eureka Server.
