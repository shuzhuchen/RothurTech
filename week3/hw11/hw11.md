# Why spring boots? pros and cons

Spring Boot is popular because it removes a lot of the setup work that developers used to do manually in the Spring Framework. It provides starter dependencies, auto-configuration, and an embedded web server like Tomcat, so we can focus on writing business logic instead of configuring infrastructure. Another advantage is that it reduces boilerplate code and makes it easy to build REST APIs quickly. One trade-off is that Spring Boot hides many implementation details behind annotations and auto-configuration. It makes development faster, but sometimes developers need a deeper understanding of what is happening under the hood when troubleshooting complex issues.

# How to start a spring boot project from scratch?

To start a Spring Boot project from scratch, I usually create a new Maven project in IntelliJ or generate one from Spring Initializr. Then I configure the Group ID, Artifact ID, and Java version, and select common dependencies such as Spring Web, Lombok, Spring Data JPA, or DevTools depending on the project requirements. Once the project is generated, Spring Boot automatically creates the basic project structure and the main application class. After that, I can start defining controllers, services, repositories, and business logic. By default, the application runs on port 8080.

# @Controller vs @RestController

Both annotations are used in the controller layer, but they serve different purposes. @Controller is used in traditional Spring MVC applications where the controller usually returns a view such as a JSP or Thymeleaf page. @RestController is more common in modern backend applications because it combines @Controller and @ResponseBody. That means Spring automatically converts Java objects into JSON or XML and sends them back to the frontend. When building REST APIs for React, Angular, or mobile applications, I normally use @RestController.

# @PathVariable vs @RequestParam

Both annotations are used to receive data from an HTTP request, but they come from different parts of the URL. @PathVariable extracts values directly from the URL path, such as /employees/1, where 1 represents the employee ID. @RequestParam reads key-value pairs from the query string, such as ?id=1. I usually use @PathVariable when the value identifies a specific resource and is part of the endpoint itself. I use @RequestParam when passing optional filters, search criteria, sorting options, or pagination parameters.

# @RequestBody vs @ResponseBody

@RequestBody is used to read data from the HTTP request body and map it into a Java object, usually a DTO. It is commonly used in POST and PUT requests when the client sends JSON data. @ResponseBody does the opposite. It tells Spring to take the returned Java object and convert it into JSON or XML in the HTTP response body. In modern applications, we usually do not use @ResponseBody directly because @RestController already includes that functionality automatically.

# how to use GetMapping, PutMapping, PostMapping, DeleteMapping, RequestMapping?

These annotations are used to map HTTP requests to controller methods. @GetMapping is typically used for reading data, @PostMapping for creating data, @PutMapping for updating data, and @DeleteMapping for deleting data. @RequestMapping is more generic and is often used at the class level to define a base URL for the controller. When designing REST APIs, I avoid putting verbs in the URL because the HTTP method already describes the action. The URL should represent the resource, while the HTTP method represents the operation.

# What is Spring Actuator?

Spring Actuator is a monitoring and management tool provided by Spring Boot. It exposes useful application metrics and health information through built-in endpoints. For example, it can show JVM memory usage, garbage collection information, thread statistics, application health, and database connection pool status. In real projects, Actuator is often integrated with Prometheus to collect metrics and Grafana to visualize them through dashboards. This helps developers monitor system performance and quickly identify production issues.

# how to achieve async in spring boot application

One common way to achieve asynchronous processing in Spring Boot is by using CompletableFuture. Instead of blocking the main thread while waiting for a long-running task, we can execute that task in a separate thread and continue processing other requests. CompletableFuture provides methods such as runAsync, supplyAsync, thenApply, and thenCompose to build asynchronous workflows. In newer Java versions such as Java 21, virtual threads can also be used to support high concurrency with much lower resource consumption than traditional platform threads.

# how does spring handle exception

Spring usually handles exceptions globally using @RestControllerAdvice. When an exception is thrown from the service layer or controller layer, Spring can automatically intercept it and route it to a centralized exception handler. Inside that handler, developers can return a consistent error response with an error message, error code, and appropriate HTTP status code. This keeps the application from crashing and ensures all APIs return errors in a standard format.

# how does spring validate data

Spring validates incoming data using validation annotations placed on DTO fields. Common examples include @NotNull, @NotBlank, @Size, and @Pattern. When a request arrives, Spring checks whether the incoming data satisfies all validation rules. If validation fails, Spring rejects the request and returns an error response, typically with an HTTP 400 status code. This helps prevent invalid data from reaching the business layer or database.

# how does spring do the log

Logging in Spring is often implemented using AOP. Instead of writing the same logging code in every service method, developers can create an Aspect that automatically intercepts method execution. The Pointcut defines where the logging should happen, and the Advice defines when it should happen, such as before or after a method call. A common use case is recording execution time, method parameters, return values, and exception details. This approach reduces duplicate code and keeps business logic clean.

# cache hit vs cache miss

A cache hit happens when the application looks for data in the cache and successfully finds it. Since the data is already in memory, the response is very fast and no database query is needed. A cache miss happens when the requested data is not found in the cache. In that case, the application has to query the database, which is usually slower. After retrieving the data, the application often stores it in the cache so future requests can become cache hits.

# do some research on Redis and have a basic understanding

Redis stands for Remote Dictionary Server. It is an in-memory data store that is commonly used as a cache, database, or message broker. Because Redis stores data in memory instead of reading from disk, it provides very fast response times, usually in milliseconds or even microseconds. In Spring Boot applications, Redis is often used to cache frequently accessed data, manage user sessions, implement rate limiting, and reduce database load. It supports different data structures such as strings, lists, sets, hashes, and sorted sets.

# @RestControllerAdvice instead of @ControllerAdvice

Both annotations are used for global exception handling, but @RestControllerAdvice is more common in modern backend applications. It combines @ControllerAdvice and @ResponseBody, which means the returned object is automatically converted into JSON or XML. If we use only @ControllerAdvice, Spring may expect a view page to be returned, which is more suitable for traditional MVC applications. Since most modern applications expose REST APIs to frontend frameworks like React or Angular, @RestControllerAdvice is usually the preferred choice.
