## What is AOP

AOP means Aspect-Oriented Programming. It is a feature in Spring that helps separate cross-cutting concerns such as logging, exception handling, security checks, and transaction management from the main business logic. Without AOP, developers would have to write the same logging or exception handling code in many different methods, which creates duplicated code and makes maintenance harder. AOP allows Spring to intercept method execution and automatically run additional logic before, after, or around the target method.

## what is JointPoint and Aspect in AOP

An Aspect is a class that contains the extra logic we want to apply across multiple parts of the application. For example, a logging aspect can automatically record method execution information for many services. A JoinPoint represents a specific point during program execution where AOP can be applied, most commonly a method execution. When Spring intercepts a method call, that method execution becomes a JoinPoint. The Aspect defines what logic to run, and the JoinPoint represents where that logic can be applied.

## what is Aspect, joinpoint, pointcut, advice, target

Aspect is a class that contains AOP-related logic such as logging, security checks, or exception handling. JoinPoint represents a specific point during application execution, usually a method execution, where AOP can be applied. Pointcut defines which JoinPoints should be intercepted by Spring. Advice defines when the additional logic should run, such as before, after, or around a method execution. Target is the original Spring bean whose methods are being intercepted by the AOP framework. Together, these components allow Spring to execute additional logic without modifying the original business code.

## ApplicationContext vs BeanFactory

Both ApplicationContext and BeanFactory are Spring IoC containers responsible for creating and managing beans. BeanFactory is the basic container and uses lazy initialization, which means a bean is created only when it is requested for the first time. ApplicationContext is a more advanced container that usually creates singleton beans during application startup. ApplicationContext also provides additional features such as event publishing, internationalization support, and integration with Spring AOP. In most modern Spring Boot applications, developers use ApplicationContext because it offers more functionality and better enterprise-level support.

## How is Spring MVC Working Flow

Spring MVC follows a layered architecture consisting of the Controller layer, Service layer, and Repository or DAO layer. When a client sends an HTTP request, the request first reaches the Controller layer. The Controller receives the request, validates the input, and forwards the request to the Service layer. The Service layer contains the business logic and may call the Repository layer if database access is required. The Repository layer communicates with the database and returns the requested data back to the Service layer. The Service layer processes the result and sends it back to the Controller. Finally, the Controller builds an HTTP response and returns it to the client.

## how does @Autowire work

@Autowired is used by Spring to perform Dependency Injection automatically. When the application starts, Spring scans and creates all registered beans in the IoC container. When a class requires a dependency, Spring looks for a matching bean and injects it automatically instead of requiring developers to create objects using the new keyword. By default, Spring performs injection based on type. In modern Spring Boot applications, constructor injection is usually preferred because it improves code readability, prevents NullPointerException issues, and makes unit testing easier.

## @Autowire and @Qualifer

By default, @Autowired injects a dependency based on its type. If there is only one implementation of an interface, Spring can inject it without any problem. However, if multiple implementations of the same interface exist, Spring will not know which bean should be injected and will throw an exception. In this situation, @Qualifier can be used together with @Autowired to specify the exact bean name that should be injected. This allows developers to choose a specific implementation when multiple candidate beans are available. Another common solution is using @Primary to mark one implementation as the default bean.

## 2 use cases for @PostConstruct and @PreDestroy

@PostConstruct is used to execute initialization logic after Spring creates a bean and injects all required dependencies. One common use case is loading configuration data or reference data into memory when the application starts. Another use case is validating required settings or connections before the application begins processing requests. @PreDestroy is used to execute cleanup logic before Spring destroys a bean during application shutdown. One common use case is closing database connections, network connections, or file streams. Another use case is saving cached data or flushing pending logs to persistent storage before the application stops.
