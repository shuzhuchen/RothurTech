## In your own words, explain security concepts for interviewer:

### 1. Encryption vs Hashing vs Encoding
**Encoding** is not security. It just transforms data from one format to another so it can be stored or transmitted safely. For example, Base64 encoding. Anyone can decode it.

**Hashing** is one-way. You cannot reverse a hash back to the original value. It is commonly used for passwords. For passwords, we should use slow salted hashing algorithms like BCrypt, Argon2, or PBKDF2.

**Encryption** is two-way. You encrypt data using a key, and later decrypt it using a key. It is used when you need to recover the original value, such as sensitive data stored in a database.

So:

```text
Encoding = reversible formatting, not secure
Hashing = one-way, used for passwords/integrity
Encryption = reversible with a key, used for sensitive data
```

Example:

```text
Password storage → hashing with BCrypt
Credit card or SSN storage → encryption
API payload over network → TLS encryption
Binary-to-text transport → Base64 encoding
```

### 2. Authentication vs Authorization
**Authentication** answers the question: Who are you?

It verifies identity. Examples include username/password login, SSO, OAuth2 login, or validating a JWT.

**Authorization** answers the question: What are you allowed to do?

It controls access after the user is authenticated. For example, an admin can delete a reward rule, but a regular user can only view their own rewards.

A simple example:

```text
Authentication: User logs in successfully.
Authorization: System checks whether that user has ROLE_ADMIN before allowing access to /admin/rewards.
```

In Spring Security, authentication usually happens through filters and authentication providers. Authorization is usually enforced through roles, authorities, URL rules, or method-level annotations like:

```java
@PreAuthorize("hasRole('ADMIN')")
```

### 3. HTTPS, certificates, key rotation
HTTPS protects data in transit. Certificates prove server identity. Key rotation reduces risk if a key is leaked or gets too old. In production, I would terminate TLS at the load balancer or API gateway, use managed certificates, avoid storing private keys in source code, and monitor certificate expiration.

### 4. JWT token structure (header, payload, signature)
JWT stands for **JSON Web Token**. It is a compact token format commonly used for stateless authentication.

A JWT has three parts:

```text
Header.Payload.Signature
```

The **header** contains metadata like the signing algorithm.
The **payload** contains claims, such as user ID, username, roles, issuer, and expiration time.
The **signature** proves that the token was issued by a trusted server and was not modified.

Example claims:

```json
{
  "sub": "user123",
  "roles": ["USER"],
  "iat": 1710000000,
  "exp": 1710003600
}
```

In a Spring Boot application, the client sends the token in the request header:

```http
Authorization: Bearer <jwt-token>
```

The server validates the signature and expiration, then creates an authenticated security context.

Important point: JWT is usually **signed**, not encrypted. Anyone can decode the payload if they have the token, so we should not put secrets or sensitive data inside the JWT.

### 5. OAuth 2.0 and OIDC
OAuth 2.0 lets an application access resources using access tokens. OIDC adds login and user identity on top of OAuth 2.0. In backend services, we usually validate JWT tokens, check expiration, issuer, audience, and scopes or roles before allowing access.

### 6. LDAP
LDAP(Lightweight Directory Access Protocol) is commonly used in enterprise systems for centralized authentication and user lookup. Instead of each application storing usernames and passwords separately, the application authenticates against LDAP or Active Directory and can use LDAP groups for role-based access control.

### 7. SQL injection and prepared statements
SQL injection is caused by treating user input as part of SQL code. To prevent it, I use prepared statements, parameterized queries, ORM methods like Spring Data JPA, input validation, least-privilege database users, and security scanning in CI/CD.
