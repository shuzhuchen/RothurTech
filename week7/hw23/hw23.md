## What is HTML and what is its main responsibility in a web page?

**Answer:**  
HTML stands for **HyperText Markup Language**. Its main responsibility is to define the structure and meaning of content on a web page.

As a senior engineer, I think of HTML as the skeleton of the page. It tells the browser what each piece of content represents: headings, paragraphs, links, images, forms, tables, buttons, and sections. HTML itself does not decide how beautiful the page looks or how interactive it is. Styling is mostly handled by CSS, and behavior is usually handled by JavaScript.

For example, when I use `<h1>Student Management System</h1>`, I am telling the browser and search engines that this is the main heading of the page. That semantic meaning is important for accessibility, SEO, and maintainability.

---

## What is an HTML file essentially made of?

**Answer:**  
An HTML file is essentially made of **elements**, and each element is usually created using tags.

A typical HTML file includes:

- A document type declaration: `<!DOCTYPE html>`
- An `<html>` root element
- A `<head>` section for metadata, page title, CSS links, and configuration
- A `<body>` section for visible page content
- HTML elements such as headings, paragraphs, buttons, forms, images, and links

Example:

```html
<!DOCTYPE html>
<html>
  <head>
    <title>Student App</title>
  </head>
  <body>
    <h1>Welcome</h1>
    <button>Login</button>
  </body>
</html>
```

In a real web application, the HTML file provides the initial structure that the browser loads and converts into the DOM.

---

## What does `<!DOCTYPE html>` do and why is it required?

**Answer:**  
`<!DOCTYPE html>` tells the browser that the document should be interpreted as a modern HTML5 document.

It is required because browsers have different rendering modes. Without the doctype, some browsers may enter **quirks mode**, where they try to mimic old browser behavior for backward compatibility. That can cause inconsistent layout and CSS behavior.

In modern development, we almost always start an HTML document with:

```html
<!DOCTYPE html>
```

It is not an HTML tag. It is an instruction to the browser about how to parse and render the document.

---

## What is an HTML tag and how does it work?

**Answer:**  
An HTML tag is a marker used to define an HTML element. Most elements have an opening tag, content, and a closing tag.

Example:

```html
<p>This is a paragraph.</p>
```

Here:

- `<p>` is the opening tag
- `This is a paragraph.` is the content
- `</p>` is the closing tag

Some tags are self-closing or void elements, meaning they do not wrap content. For example:

```html
<img src="logo.png" alt="Company logo">
<br>
<input type="text">
```

Tags tell the browser what type of element to create in the DOM. For example, `<button>` creates a button element, `<a>` creates a hyperlink, and `<form>` creates a form container.

---

## What is the difference between the <head> and <body> sections?

**Answer:**  
The `<head>` section contains metadata and resources used by the page, while the `<body>` section contains the visible content shown to the user.

The `<head>` usually includes:

- Page title
- CSS links
- JavaScript references
- Metadata like character encoding and viewport settings
- SEO-related tags

Example:

```html
<head>
  <title>Student Management System</title>
  <meta charset="UTF-8">
  <link rel="stylesheet" href="style.css">
</head>
```

The `<body>` contains what users actually see and interact with:

```html
<body>
  <h1>Students</h1>
  <button>Add Student</button>
</body>
```

In short, `<head>` supports the page; `<body>` represents the page content.

## What is an HTML attribute and why is it needed?

**Answer:**  
An HTML attribute provides additional information or configuration for an HTML element.

Attributes are written inside the opening tag.

Example:

```html
<a href="https://example.com" target="_blank">Visit Site</a>
```

Here:

- `href` tells the browser where the link goes
- `target="_blank"` tells the browser to open it in a new tab

Another example:

```html
<input type="email" placeholder="Enter your email" required>
```

Attributes are needed because they control behavior, provide accessibility information, connect elements to CSS or JavaScript, and define values such as URLs, IDs, classes, input types, and validation rules.

Common attributes include `id`, `class`, `src`, `href`, `alt`, `type`, `value`, `name`, and `disabled`.

## How does the browser parse HTML and convert it into the DOM?

**Answer:**  
When the browser receives an HTML file, it reads the HTML from top to bottom and converts it into a tree-like structure called the **DOM**, which stands for **Document Object Model**.

The process is roughly:

1. The browser downloads the HTML file.
2. It tokenizes the HTML into meaningful pieces such as tags, attributes, and text.
3. It creates nodes for each element.
4. It builds a DOM tree based on parent-child relationships.
5. CSS is parsed into the CSSOM.
6. The browser combines the DOM and CSSOM to render the page.
7. JavaScript can later read or modify the DOM dynamically.

For example, this HTML:

```html
<body>
  <h1>Hello</h1>
  <button>Click</button>
</body>
```

becomes a DOM tree where `body` is the parent node, and `h1` and `button` are child nodes.

This is why JavaScript can do things like:

```javascript
document.querySelector("button").textContent = "Clicked";
```

It is not directly changing the original HTML file. It is changing the DOM representation in memory.

## What is CSS and what problem does it solve?

**Answer:**  
CSS stands for **Cascading Style Sheets**. It is used to control the presentation and layout of HTML elements.

HTML defines what the content is. CSS defines how that content looks.

CSS solves the problem of separating structure from presentation. Without CSS, we would have to mix styling directly into HTML, which becomes difficult to maintain in larger applications.

For example:

```css
button {
  background-color: blue;
  color: white;
  padding: 10px 16px;
}
```

This allows all buttons to share a consistent style. In production front-end applications, CSS is responsible for layout, spacing, colors, typography, responsiveness, animations, and visual consistency.

---

## Why is CSS not considered a programming language?

**Answer:**  
CSS is not usually considered a programming language because it does not contain core programming features like control flow, loops, functions in the traditional sense, or general-purpose logic execution.

CSS is a **declarative styling language**. We describe what the page should look like, and the browser decides how to apply those rules.

For example:

```css
.card {
  border: 1px solid #ccc;
  padding: 16px;
}
```

This rule declares that elements with class `card` should have a border and padding. It does not perform calculations, make business decisions, call APIs, or manage application state.

That said, modern CSS has powerful features like variables, media queries, animations, grid, flexbox, and functions like `calc()`. But its primary purpose is still styling, not general-purpose programming.

## What are the three ways to apply CSS to an HTML page?

**Answer:**  
There are three common ways to apply CSS to an HTML page:

1. **Inline CSS**  
   CSS is written directly on an element using the `style` attribute.

```html
<p style="color: red;">Hello</p>
```

2. **Internal CSS**  
   CSS is written inside a `<style>` tag in the `<head>` section.

```html
<head>
  <style>
    p {
      color: red;
    }
  </style>
</head>
```

3. **External CSS**  
   CSS is written in a separate `.css` file and linked to the HTML file.

```html
<link rel="stylesheet" href="style.css">
```

In real projects, external CSS is preferred because it keeps the code clean, reusable, and easier to maintain.

---

## Why are inline styles generally not recommended?

**Answer:**  
Inline styles are generally not recommended because they mix content and presentation directly inside the HTML.

Example:

```html
<button style="background-color: blue; color: white; padding: 10px;">Save</button>
```

This works, but it creates several problems:

- It is hard to reuse across multiple elements.
- It makes HTML harder to read.
- It is harder to maintain at scale.
- It can override external styles unexpectedly.
- It makes consistent design more difficult.

As a senior engineer, I prefer CSS classes because they are reusable and easier to change globally.

Better approach:

```html
<button class="primary-button">Save</button>
```

```css
.primary-button {
  background-color: blue;
  color: white;
  padding: 10px;
}
```

Inline styles are acceptable for quick testing or dynamic styles generated by JavaScript, but they should not be the default approach.

## What is the difference between id selectors and class selectors in CSS?

**Answer:**  
An `id` selector targets one unique element, while a `class` selector targets one or more elements.

An `id` is written with `#` in CSS:

```html
<div id="login-form"></div>
```

```css
#login-form {
  border: 1px solid black;
}
```

A `class` is written with `.` in CSS:

```html
<button class="primary-button">Save</button>
<button class="primary-button">Submit</button>
```

```css
.primary-button {
  background-color: blue;
}
```

Key differences:

- `id` should be unique on the page.
- `class` can be reused on many elements.
- `id` has higher CSS specificity than `class`.
- Classes are preferred for styling because they are reusable and scalable.

In modern front-end development, I use IDs mainly for unique anchors, form labels, or JavaScript hooks when needed, but I generally use classes for styling.

## What is the difference between margin and padding?

**Answer:**  
`margin` is the space outside an element, while `padding` is the space inside an element between the content and the border.

Think of a box:

```text
margin  -> space outside the border
border  -> edge of the element
padding -> space inside the border
content -> text/image/content
```

Example:

```css
.card {
  margin: 20px;
  padding: 16px;
  border: 1px solid #ccc;
}
```

Here:

- `margin: 20px` creates space between the card and other elements.
- `padding: 16px` creates space between the card border and the content inside it.

In layout work, margin is used for spacing between components, while padding is used for spacing inside a component.

## What is the difference between position: relative and position: absolute?

**Answer:**  
`position: relative` positions an element relative to where it would normally be in the document flow. `position: absolute` removes the element from the normal document flow and positions it relative to the nearest positioned ancestor.

Example of relative:

```css
.box {
  position: relative;
  top: 10px;
  left: 20px;
}
```

The element still occupies its original space, but visually moves 10px down and 20px right.

Example of absolute:

```css
.container {
  position: relative;
}

.badge {
  position: absolute;
  top: 0;
  right: 0;
}
```

Here, `.badge` is positioned relative to `.container`, because `.container` has `position: relative`.

In real applications, a common pattern is to set the parent to `position: relative` and the child to `position: absolute` when placing badges, dropdowns, tooltips, or icons inside a component.

## What is JavaScript used for in a web application?

**Answer:**  
JavaScript is used to add behavior and interactivity to a web application.

HTML gives the page structure. CSS gives it styling. JavaScript makes it dynamic.

JavaScript can be used to:

- Handle button clicks
- Validate forms
- Call backend APIs
- Update the DOM dynamically
- Show or hide content
- Manage application state
- Build single-page applications using frameworks like Angular, React, or Vue

For example, in a Student Management System, JavaScript can handle login, send credentials to the backend, store a JWT token, fetch students, render a table, and perform create, update, and delete operations without reloading the entire page.

## What are the two ways to include JavaScript in an HTML file?

**Answer:**  
There are two common ways to include JavaScript in an HTML file:

1. **Internal JavaScript** using a `<script>` tag:

```html
<script>
  console.log("Hello from JavaScript");
</script>
```

2. **External JavaScript** using a separate `.js` file:

```html
<script src="app.js"></script>
```

In real projects, external JavaScript is preferred because it keeps the code organized and reusable.

A common best practice is to place the script before the closing `</body>` tag or use the `defer` attribute in the `<head>`:

```html
<script src="app.js" defer></script>
```

Using `defer` allows the HTML to be parsed first before the JavaScript runs, which helps avoid errors when JavaScript tries to access DOM elements that have not been created yet.

## What is a variable in JavaScript and what types of values can it store?

**Answer:**  
A variable in JavaScript is a named container used to store a value.

Modern JavaScript uses `let` and `const` to declare variables.

Example:

```javascript
let studentName = "Ada";
const studentId = 101;
```

A JavaScript variable can store many types of values, including:

- String: `"Hello"`
- Number: `25`
- Boolean: `true` or `false`
- Object: `{ name: "Ada", age: 20 }`
- Array: `["Math", "Science"]`
- Null: `null`
- Undefined: `undefined`
- Function: `function() {}`

Example:

```javascript
const student = {
  id: 1,
  name: "Ada",
  active: true,
  majors: ["Computer Science"]
};
```

As a best practice, I use `const` by default and use `let` only when the variable needs to be reassigned.

## How does JavaScript interact with HTML elements through the DOM?

**Answer:**  
JavaScript interacts with HTML through the DOM, which is the browser's in-memory representation of the page.

JavaScript can select HTML elements, read their values, update their content, change styles, add or remove classes, create new elements, and respond to user actions.

Example:

```html
<h1 id="title">Welcome</h1>
<button id="changeBtn">Change</button>
```

```javascript
const title = document.getElementById("title");
const button = document.getElementById("changeBtn");

button.addEventListener("click", function () {
  title.textContent = "Hello, Student!";
});
```

Here, JavaScript finds the heading and button in the DOM. When the button is clicked, JavaScript updates the heading text.

In modern frameworks like Angular, we usually do not manipulate the DOM manually as much. Instead, we bind data to templates, and the framework updates the DOM for us.

## What are loops used for in JavaScript, and can you give an example use case?

**Answer:**  
Loops are used to repeat a block of code multiple times.

They are useful when working with lists of data, such as rendering students, validating form fields, or processing API responses.

Example use case: displaying a list of students.

```javascript
const students = ["Ada", "Grace", "Alan"];

for (let i = 0; i < students.length; i++) {
  console.log(students[i]);
}
```

A more modern approach is using `forEach`:

```javascript
students.forEach(function (student) {
  console.log(student);
});
```

In a real front-end application, if the backend returns a list of students, JavaScript can loop through the array and create table rows or cards for each student.

Example:

```javascript
students.forEach(student => {
  const row = document.createElement("tr");
  row.textContent = student.name;
  document.querySelector("table").appendChild(row);
});
```

## What is an event listener and why is it important in front-end development?

**Answer:**  
An event listener is a function that waits for a specific user action or browser event and runs code when that event happens.

Common events include:

- `click`
- `submit`
- `input`
- `change`
- `keydown`
- `mouseover`

Example:

```html
<button id="loginBtn">Login</button>
```

```javascript
const loginButton = document.getElementById("loginBtn");

loginButton.addEventListener("click", function () {
  console.log("Login button clicked");
});
```

Event listeners are important because front-end applications are user-driven. The application needs to respond when users click buttons, type into forms, submit data, navigate pages, or interact with UI components.

For example, in a login page, an event listener can listen for the form submission, prevent the default page reload, collect the username and password, call the backend login API, and then redirect the user after a successful login.
